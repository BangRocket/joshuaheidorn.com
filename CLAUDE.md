# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal resume / portfolio / blog site for Joshua Heidorn (joshuaheidorn.com). Deployed to Joshua's **paid** Cloudflare account. Not static — runs on Workers with D1 + R2.

Full design rationale lives in `docs/plans/2026-04-23-personal-site-design.md`. Read that before making architectural decisions.

## Stack

- **Astro 6** (SSR via `@astrojs/cloudflare`, `output: "server"`)
- **[EmDash CMS](https://github.com/emdash-cms/emdash)** — Astro-native CMS, installed as an **upstream dependency** (do not fork; do not vendor). D1 + R2 bindings are wired in `astro.config.mjs`.
- **Cloudflare Workers + D1 + R2** — paid tier. `worker_loaders` binding stays on in `wrangler.jsonc` for EmDash plugin sandboxing (sandbox runner is already wired into `astro.config.mjs`).
- **React 19** — islands only, via `@astrojs/react`.
- **Tailwind v4** via `@tailwindcss/vite` — no `tailwind.config.js`. Theme tokens live in `src/styles/global.css` and `theme.css` under `@theme`.
- **shadcn + RetroUI** — `components.json` is a shadcn config (`style: "base-nova"`, `@/components` alias, `lucide` icons). RetroUI components install through the shadcn CLI from their registry (`npx shadcn@latest add 'https://retroui.dev/r/<name>.json'`) and land in `src/components/retroui/` — that path is RetroUI's convention, not shadcn's default `ui/`.
- **TypeScript** — `@/*` alias → `./src/*` (see `tsconfig.json`). `emdash-env.d.ts` is **auto-generated by EmDash on dev server start** — do not edit. `worker-configuration.d.ts` is generated by Wrangler — do not edit.
- **yarn (1.x classic)** — enforced. Joshua's `~/package.json` pins `packageManager: yarn@1.22.22`, which blocks pnpm in this subtree. Do not try to switch to pnpm/npm without discussing.

## Architecture

- **Worker entry:** `src/worker.ts` re-exports the `@astrojs/cloudflare` handler plus `PluginBridge` from `@emdash-cms/cloudflare/sandbox`. Keep this file tiny — Astro generates everything around it.
- **Single layout:** `src/layouts/Base.astro` owns the chrome (nav, footer, theme switcher, site-wide `LiveSearch`, font preload, `<EmDashHead>`/`<EmDashBodyStart>`/`<EmDashBodyEnd>`). Every page imports it. SEO/meta is passed in via props and rendered by `EmDashHead`.
- **EmDash content access:** import from `"emdash"` — `getEmDashCollection(name)`, `getEntryTerms(...)`, `getMenu(...)`, `getSiteSettings()`. Live collection wiring is `src/live.config.ts` (a single `_emdash` live collection backed by `emdashLoader()`). **Pages that read EmDash content must call `Astro.cache.set(cacheHint)`** after fetching, to propagate the collection's cache hint to the edge.
- **Fonts** are loaded via Astro's font integration in `astro.config.mjs` (`fontProviders.google()`) and exposed as CSS vars `--font-sans` (Space Grotesk), `--font-head` (Archivo Black), `--font-mono` (JetBrains Mono). `Base.astro` preloads them with `<Font />`.

## Content model (hybrid)

- **In EmDash (D1):** `posts`, `projects`, `pages`. Current field shapes are mirrored in the generated `emdash-env.d.ts`.
- **In repo (JSON):** `src/data/resume.json` (headlines, contact, experience, education) and `src/data/skills.json` (grouped by category). Both have JSON Schema siblings (`*.schema.json`) — keep schemas in sync when adding fields.
- Resume + skills render at build/request time by importing JSON directly into Astro pages. Posts + projects fetch from EmDash at request time via `getEmDashCollection`.

Don't move resume/skills into EmDash without revisiting the design — the hybrid split was a deliberate call (git diff for resume edits, CMS UX for content edits).

## Commands

- `yarn install` (or just `yarn`)
- `yarn dev` — Astro dev server with Wrangler/Miniflare (local D1 + R2)
- `yarn build` — production build
- `yarn preview` — preview the build locally
- `yarn deploy` — `astro build && wrangler deploy`
- `yarn typecheck` — `astro check` (the only type-checker in the repo)
- `yarn bootstrap` — `emdash init && emdash seed` (first-time or after D1 rebuild)
- `yarn seed` — re-apply `seed/seed.json` to local D1

No test runner, no lint runner, no formatter config. Ask before adding one.

## EmDash: admin is broken — author via seed

EmDash's admin UI crashes with React error #300 because `@cloudflare/kumo`'s `Sidebar` export is lost through the bundler ([upstream #469](https://github.com/emdash-cms/emdash/issues/469)). Until that is fixed, content authoring happens via **`seed/seed.json` → `yarn seed` → redeploy**. The full workflow (including how to push seed data to remote D1) is in `docs/emdash-gaps.md`. **Do not waste cycles trying to "fix" the admin — the bug is in a dep, not our code.**

`docs/emdash-gaps.md` is the running log of upstream gaps + workarounds. Check it before assuming EmDash behavior is wrong in this repo.

## Gap-fill posture

EmDash will have gaps. When you (or future Claude) hit one:

1. **First**: check if it's addressable via EmDash's plugin system. Plugins go in `/plugins/`, are capability-scoped, run in sandboxed Worker isolates.
2. **If plugin can't do it**: open an issue upstream. Possibly a PR.
3. **Last resort**: fork. Forks bitrot on a moving upstream — default to avoiding.

Plugin work is out of scope for v1. But do not disable `worker_loaders` in `wrangler.jsonc` — we want plugins to be a deploy-config switch later, not a code change.

## RetroUI integration notes

- RetroUI components ship via the shadcn registry (see Stack section). Added components land at `src/components/retroui/` (e.g., `Button.tsx`).
- If the shadcn CLI misbehaves in this Astro layout, copy RetroUI component source from their docs by hand. Once added, components are owned source — edit them freely.
- Use `client:visible` (or no client directive) on React components whenever possible; don't reach for `client:load` unless the component actually needs JS on first paint.
- RetroUI's retro styling applies to **chrome** (cards, buttons, hero blocks, skill chips). Blog post body prose stays readable and relatively un-retro.

## Out of scope for v1

Comments, multi-user auth, analytics, search over projects, PDF export of resume, i18n. Do not build these speculatively.

## Conventions

- Functional React components only
- `git add .` is forbidden. Add files by name.
- Tailwind utility classes in JSX/Astro; global CSS only where RetroUI's theme tokens or font imports need it
- Keep the component tree shallow — this is a resume site, not an app. No abstractions until 3+ concrete usages.
